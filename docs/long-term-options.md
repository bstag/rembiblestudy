# Long-term options

Keep the notebook action on firmware builds where it has been tested. Use the desktop CLI as the portable entry point for Scripture and quotes. With phrase discovery in place, add book and page results as separate kinds of evidence so a search hit does not become a citation by accident.

## reMarkable support and firmware

- **Official developer access.** On the Paper Pro, enabling Developer Mode gives root SSH access over USB, performs a factory reset, and disables most secure-boot checks while keeping disk encryption enabled. reMarkable documents recovery mode as the way to exit Developer Mode. Recovery can attempt to preserve user data or perform a factory reset. reMarkable excludes defects caused by modifications from its limited warranty and Protection Plan. [Developer Mode](https://developer.remarkable.com/documentation/developer-mode) · [Recovery Mode](https://developer.remarkable.com/documentation/recovery-mode) · [Software recovery](https://support.remarkable.com/articles/Knowledge/Software-recovery)
- **Updates and backups.** Automatic update downloads are on by default and can be switched off. Before resetting or changing firmware on the development tablet, verify important notebooks in the cloud and keep independent USB downloads or PDF exports. USB accepts `.rmdoc` for import, so test a round trip with a disposable notebook when editable recovery matters. PDF is a readable snapshot. Without Connect, documents that have gone more than 50 days without being opened and synced stop syncing. On an already modified device, reMarkable also documents copying the raw document directory while Xochitl is stopped. Keep that copy as a separate archive and validate restoration on the target build before relying on it. [Updates](https://support.remarkable.com/s/article/How-to-update-your-reMarkable-and-apps) · [Import and export](https://support.remarkable.com/articles/Knowledge/Importing-and-exporting-files) · [Cloud sync](https://support.remarkable.com/s/article/Pair-your-reMarkable-with-the-cloud) · [Xochitl document storage](https://developer.remarkable.com/documentation/xochitl)
- **Notebook action SDK.** reMarkable publishes a Yocto-based cross-compilation SDK and a Qt Quick guide for running a separate app. The guide stops Xochitl before launching the example. Xochitl is proprietary, and reMarkable gives no cross-version compatibility guarantee. The public developer docs show no supported extension API for adding a lasso action, receiving selected strokes, invoking handwriting recognition, or inserting ink into an open notebook. That is a conclusion about the documented public surface. [Developer documentation](https://developer.remarkable.com/documentation) · [SDK](https://developer.remarkable.com/documentation/sdk) · [Qt Quick guide](https://developer.remarkable.com/documentation/qt_epaper) · [Xochitl](https://developer.remarkable.com/documentation/xochitl)

## Integration choices

| Option | Fit and tradeoff |
| --- | --- |
| **Current XOVI/QMLDiff action** | The repo targets Paper Pro firmware `3.29.1.0` and reports a hands-on lasso-to-passage preview. XOVI loads extensions via `LD_PRELOAD`, the resource rebuilder patches Qt resources with QMLDiff, and the command executor lets QML call the Rust helper. Upstream calls for rebuilding the hash table after updates. Treat that as one porting step and retest selection, recognition, preview, ink placement, and rollback on each candidate firmware. [Project README](../README.md#tablet-integration) · [Installer](../tablet/install.ps1) · [XOVI](https://github.com/asivery/xovi) · [QMLDiff](https://github.com/asivery/qmldiff) · [reMarkable XOVI extensions](https://github.com/asivery/rm-xovi-extensions) |
| **Desktop CLI and stock reMarkable workflow** | Use the existing desktop Scripture lookup today. Expose quote lookup there next and produce copyable text with attribution, plus an optional PDF for import and annotation. With Connect, users can paste typed results into an existing notebook in the desktop app. USB PDF import works without Connect or Developer Mode. The user transcribes the query or uses stock handwriting conversion on a separate page, then moves the result manually. [CLI entry point](../src/main.rs) · [Desktop text editing](https://support.remarkable.com/articles/Knowledge/Using-typed-text-on-your-reMarkable) · [Handwriting conversion](https://support.remarkable.com/articles/Knowledge/Convert-handwritten-notes-into-text) · [USB import](https://support.remarkable.com/articles/Knowledge/Importing-and-exporting-files) |
| **Separate tablet app** | AppLoad can host a windowed or full-screen lookup app under XOVI. The official Qt Quick toolchain also allows a stand-alone app. Both can provide typed lookup on the tablet. Selection in an existing notebook and native ink insertion would still need their own integration. Consider this if desktop handoff proves too cumbersome and typed on-device lookup is enough. [AppLoad](https://github.com/asivery/rm-appload) · [Qt Quick guide](https://developer.remarkable.com/documentation/qt_epaper) |
| **Notebook file tooling** | A desktop tool can inspect exported or copied notebooks. Editing raw files adds format and sync compatibility work, and reMarkable directs developers to stop Xochitl before accessing stored documents. If editable batch output becomes important, test generation and re-import with disposable copies. Keep live notebook writes out of this path. [Xochitl document storage](https://developer.remarkable.com/documentation/xochitl) · [rmscene](https://github.com/ricklupton/rmscene) |

## Phrase, book, and page lookup

**Existing behavior.** The tablet and desktop search the NIV and English Wikiquote for a bare phrase. An author-qualified query parses the named English Wikiquote page and can return similar wording with a revision link. **As heard** preserves the entered wording on the tablet. [Rust entry point](../src/main.rs) · [Wikiquote matcher](../src/quotes.rs) · [Tablet workflow](../README.md#tablet-integration)

1. **Search Wikiquote by phrase.** Version `0.2.0` uses MediaWiki full-text search to shortlist up to four pages, then checks their rendered entries for exact wording. Results show the Wikiquote revision and available citation text. The author-qualified search also labels similar wording. Wikiquote distinguishes sourced, attributed, and misattributed entries, and individual quotations carry their own rights. [MediaWiki search](https://www.mediawiki.org/wiki/API:Search) · [MediaWiki parse](https://www.mediawiki.org/wiki/API:Parsing_wikitext) · [Wikiquote sourcing](https://en.wikiquote.org/wiki/Wikiquote:Quotability) · [Wikiquote copyright guidance](https://en.wikiquote.org/wiki/Wikiquote:Copyrights#Licensing_and_downstream_use)
2. **Add Google Books for discovery.** Search volumes by phrase, with title, author, or ISBN filters when known. A result may offer a search snippet and a preview link, with access varying by volume and location. Show a book lead with the edition identifiers available and link to the preview. The volume result schema gives no page locator for the snippet. Attribute Google results as required and leave the page blank until someone checks that edition. [Books API guide](https://developers.google.com/books/docs/v1/using) · [Volume fields](https://developers.google.com/books/docs/v1/reference/volumes) · [Branding](https://developers.google.com/books/branding)
3. **Use Open Library to identify editions and check scans.** The catalog API returns work and edition metadata and can include availability. Search Inside can find phrases in indexed scans. Start by linking to its reader or search. The documented per-book OCR endpoint is experimental and tied to a specific Internet Archive item. Confirm wording and the printed page label against that edition’s scan. A scan leaf or index can serve as a locator when the printed page is unknown. [Catalog API](https://openlibrary.org/dev/docs/api/search) · [Search Inside](https://blog.openlibrary.org/2024/10/03/improving-search-removing-dead-ends/) · [Per-book OCR API](https://openlibrary.org/dev/docs/api/search_inside) · [Reader page links](https://openlibrary.org/dev/docs/bookurls)
4. **Add a small local source library if repeated lookups justify it.** Index public-domain, licensed, or authorized texts locally with SQLite FTS5 phrase search. Record the source, edition, rights, and a page label or section for each indexed passage. Reflowable transcriptions can supply chapter or section citations. Use page-mapped scans or PDFs when printed pagination matters. This gives offline lookup within the imported collection. [SQLite FTS5](https://www.sqlite.org/fts5.html) · [Project Gutenberg permissions and source editions](https://www.gutenberg.org/policy/permission.html)

Have the CLI and tablet share the same lookup and result fields. Keep provider, wording, work, edition, locator, source link, and verification status where available. Show the result for review before inserting it, especially when OCR, approximate wording, or a limited preview supplies the evidence.
